**Goal:** Move the homepage of dreaminreality.co.uk to the dark theme and add an eight-stage "product development timeline" whose stages each tie to one service, joined by a line that meanders from side to side with a light that travels to each stage as it snaps into view.

### The meander line and the light (from `lg` up)

- One `<svg aria-hidden="true">` overlay, `pointer-events-none absolute inset-0 hidden h-full w-full lg:block`, inside the timeline section, drawn in the section's own pixel coordinates (viewBox = measured width × height; no `preserveAspectRatio="none"`, no `vector-effect`).
- **Geometry is measured, not assumed.** Start point: bottom centre of the `[data-meander-start]` header. Then the centre of each `[data-meander-node]` station, all relative to the section. Recomputed by a `ResizeObserver` on the section.
- **Eight segments**, one per stage: start → station 01, then station to station. Each is one cubic curve with vertical tangents at both ends, so the line leaves a station straight down, swings across the page and enters the next station from above. That is the side-to-side meander.
- **Base line:** every segment `stroke-line` 1px, `fill="none"`.
- **Lit trail:** the same segments again in `stroke-accent-visual` 1.5px, each revealed with framer-motion `pathLength`.
- **Light:** a solid cyan dot (`r=5`) with a 20% opacity ring (`r=11`), drawn at the tip of the lit trail. No blur or filter (`.ux-profile.md` bans neon glows; the ring carries the "light" reading). The stations are `bg-navy` and sit above the SVG, so the light docks into a station and the station lights.
- **Progress value `p`:** one framer-motion `MotionValue`, 0 to 8. `p = 0` is the start point; `p = k` is station `k`. Segment `k` (0-based) is revealed by `clamp(p - k, 0, 1)`. The light sits at `getPointAtLength(local × length)` of the segment it is on.
- **What moves it:** a passive scroll listener (throttled with `requestAnimationFrame`) computes `stopAt(tops, innerHeight)` from the stage `li` tops. When the stop changes, animate `p` to it: `travelMs` duration, ease-in-out. One wheel step down plays one segment (1.2 s); scrolling back rewinds (0.6 s). Above the timeline the stop is 0 and nothing is lit.
- **Station state:** stations below the current stop are "passed", the one at the stop is "current" once `p` reaches it (set on animation complete, so the station lights as the light arrives).
- **Reduced motion:** the line is drawn; `p` jumps (duration 0); the light dot is not rendered.
- **No JavaScript:** no SVG; stations idle; all text present.

### Task 1: Meander maths

**Files:**
- Create: `src/lib/meander.mjs`
- Test: `src/lib/meander.test.mjs`

**Interfaces:**
- Produces:
  - `stopAt(tops: number[], viewportHeight: number): number`: how many stage tops (viewport-relative px) are at or above the middle of the viewport. 0 to `tops.length`. Non-finite entries count as not reached.
  - `meanderSegments(start: {x, y}, nodes: {x, y}[]): string[]`: one SVG path `d` per node. Segment `k` runs from the previous point to `nodes[k]` as `M x0 y0 C x0 ym x1 ym x1 y1` with `ym = (y0 + y1) / 2`, every number rounded to an integer.
  - `travelMs(from: number, to: number): number`: 0 when equal, 1200 when `to > from`, 600 when `to < from`, whatever the distance.

- [ ] **Step 1: Write the failing test**

```js
import test from "node:test";
import assert from "node:assert/strict";
import { stopAt, meanderSegments, travelMs } from "./meander.mjs";

test("stopAt counts stages whose top has reached mid-viewport", () => {
  assert.equal(stopAt([900, 1700, 2500], 800), 0);
  assert.equal(stopAt([240, 1040, 1840], 800), 1);
  assert.equal(stopAt([-560, 240, 1040], 800), 2);
  assert.equal(stopAt([-2000, -1200, -400], 800), 3);
  assert.equal(stopAt([400, 1200], 800), 1); // exactly at the middle counts
});
test("stopAt survives bad input", () => {
  assert.equal(stopAt([], 800), 0);
  assert.equal(stopAt([NaN, 100], 800), 1);
});
test("meanderSegments draws S-curves with vertical tangents", () => {
  assert.deepEqual(
    meanderSegments({ x: 600, y: 200 }, [{ x: 850, y: 550 }, { x: 350, y: 1300 }]),
    ["M600 200 C600 375 850 375 850 550", "M850 550 C850 925 350 925 350 1300"]
  );
});
test("meanderSegments rounds and handles no nodes", () => {
  assert.deepEqual(meanderSegments({ x: 0.4, y: 0.6 }, [{ x: 10.5, y: 21 }]), [
    "M0 1 C0 11 11 11 11 21",
  ]);
  assert.deepEqual(meanderSegments({ x: 0, y: 0 }, []), []);
});
test("travelMs is one fixed duration per direction", () => {
  assert.equal(travelMs(2, 2), 0);
  assert.equal(travelMs(2, 3), 1200);
  assert.equal(travelMs(0, 8), 1200);
  assert.equal(travelMs(5, 4), 600);
  assert.equal(travelMs(8, 0), 600);
});
```

Note for the rounding test: round the inputs first (`0.4 → 0`, `0.6 → 1`, `10.5 → 11`), then take `ym = Math.round((y0 + y1) / 2)` of the rounded values (`(1 + 21) / 2 = 11`).

## Decisions made by the planner (change before handing off if wrong)

1. **Stage order and mapping.** Eight stages, one per existing service card. Reverse engineering is the entry stage ("sketch, sample or existing part"); renders sit at stage 07, after drawings; supplier liaison is one sentence in stage 08, with no link, because it has no page yet.
2. **Length.** Twelve snap frames. That is eleven wheel steps to reach the testimonials. The intro has a "See the eight stages" link; there is no skip link past the timeline. If it feels long in the browser, the cheapest fix is two stages per frame (four frames), which this structure allows without changing the maths.
3. **Station visuals.** Version one uses the eight existing icons inside the stations. Small moving SVG or three.js vignettes per stage would be a follow-up, one stage at a time.
4. **The light.** A solid dot with a soft ring and a lit trail; no blur glow, because the UX profile bans neon glows.
5. **Hero.** Kept as the still cube render, made static. The "bright, constant animation" rule for landing frames is not met here; a turning cube needs a GLB export of the logo from SolidWorks.
6. **Voice.** Intro and stages are third person, like `/about`. The hero still says "We produce".
7. **CTA wording.** "Contact" becomes "Send your brief", as on every dark page.
